> **마케팅 루프(항상):** 감지 → 판단 → 제작 → 배포 → 학습. 측정 없는 게시 금지. 자세히 [[method]].

# local — 오프라인 접점이 있으면 여기가 1순위다 (LOC-01~11)

매장·쇼룸·방문 서비스처럼 **오프라인 접점이 있는 B2C**라면 채널 우선순위 1번은 광고도 인스타도 아니고 네이버 플레이스다. "동네명+업종"으로 검색하는 사람은 이미 지갑을 연 사람이고, 그 검색과 지도 앱의 입구는 사실상 플레이스 하나다. 게다가 **등록·운영이 무료다** — 영업시간·가격·사진·예약·상담까지 담기는, 돈 안 드는 홈페이지가 하나 생기는 셈이다.

함정은 두 개다. 첫째, **등록만 하고 방치.** 빈칸투성이 플레이스는 순위에서 밀리고, 어렵게 들어온 사람도 전화 한 통 없이 나간다. 둘째, **리뷰 조작 유혹.** 자작 리뷰·대가 미표시 후기는 표시광고법 위반(제재 대상은 광고주)에 플레이스 자체 제재까지 겹쳐 노출이 통째로 사라진다. 이 채널의 돈 공식은 단순하다: 검색·지도 노출 → 플레이스 방문 → 전화·예약·길찾기 → 매장 방문 → **톡톡 메시지로 재방문**.

## 실행 유형: [A] 정보 완성도 진단·업체 설명·대표 키워드·소식/쿠폰 초안·톡톡 메시지 초안·상담 답변 초안·순위/유입 확인은 질문 없이 실행 / [P] 스마트플레이스 센터의 게시·저장 버튼(공식 공개 게시 API 확인 필요 — 사람 몫)과 플레이스 광고 집행·증액(돈 나가는 확대)은 승인 / [H] 리뷰 자작·구매·순위 조작 프로그램은 어떤 요청에도 하지 않는다 — approval_mode 참조. 유형별 차이는 [[role]].

## 0. 준비
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,products,audiences,tone,claims}.md 2>/dev/null
marketing-copilot library list content --limit 20   # channel=local 레코드(소식·쿠폰·메시지)를 골라 본다
```
- 오프라인 접점이 없는 순수 온라인 사업이면 이 스킬은 후순위다 — [[blog]]·[[instagram]]으로.
- 업체명·주소·영업시간·가격은 **컨텍스트에 있는 값만** 쓴다. 없으면 지어내지 말고 "확인 필요"로 비워서 사용자에게 채우게 한다.

## 1. 비용 지도 — 도구는 전부 무료, 광고만 돈이다 (LOC-01)

| 도구 | 비용 | 뭐 하는 물건인가 |
|---|---|---|
| 스마트플레이스 등록·운영 | **무료** | 검색·지도 노출 + 업체 정보 페이지(사실상 무료 홈페이지) |
| 네이버 톡톡 상담 | **무료** | 방문 전 문의 채팅 — 응대 초안은 자동으로 만든다 |
| 톡톡 마케팅 메시지 | **월 1회 무료** | 알림받기·최근 방문·최근 결제 고객에게 발송 — 재방문 엔진 |
| 네이버 예약·주문 | **무료** | 예약·주문 접수 (결제 수수료 등 세부 요금은 확인 필요) |
| 스마트콜 | **무료** | 전화 추적 번호 — 어디서 온 전화인지 측정된다 |
| 플레이스 광고·지역소상공인 광고 | **별도 광고비** (도구 이용료 0원) | 무료 최적화를 다 한 다음의 증폭 수단 |

무료 도구를 안 켜놓고 광고부터 태우는 것이 이 채널의 가장 흔한 낭비다. 순서는 항상 **무료 최적화 → 측정 → 광고**.

## 2. ★정보 완성도 — 여기서 승부의 절반이 난다 (LOC-02)

| 항목 | 초안 담당 | 비고 |
|---|---|---|
| 업종 카테고리 | 🤖 추천 | 검색어와 직결 — 잘못 고르면 아예 안 뜬다 |
| 업체 설명 | 🤖 자동 초안 | brand·products 컨텍스트에서 생성, 지역명+업종 키워드를 자연스럽게 |
| 대표 키워드 | 🤖 자동 초안 | "지역명+업종" 조합 우선 — 선정 로직은 [[blog]] 키워드 절과 같다 |
| 영업시간·가격·메뉴 | 👤 사실 확인 | 컨텍스트 밖 값은 "확인 필요" — 틀리면 부정 리뷰로 돌아온다 |
| 사진 | 사용자 소재 우선 | 실물 컷이 항상 낫다. 부족분 도해·배너만 [[imagefactory]] 발주 |
| 편의시설·주차·SNS 링크 | 🤖 진단 → 👤 확인 | 빈칸 목록을 뽑아 한 번에 채우게 한다 |

- 흐름: **빈칸 진단 → 초안 일괄 생성 → 사용자는 사실확인 + 저장 버튼.** "설명 문구를 고민해보세요"라고 넘기지 않는다 — 초안은 항상 이쪽 몫이다.

## 3. 플레이스 순위 요소 — 아는 것과 추정을 구분한다 (LOC-03)

| 요소 | 방향 | 근거 |
|---|---|---|
| 정보 완성도 | 항목이 채워질수록 노출 기회↑ | 공식 안내 |
| 리뷰 수·최신성 | 꾸준히 새 리뷰가 쌓이는 업체가 유리 | 리뷰 반영은 공식, 가중치·최신성 세부는 업계 추정 |
| 저장(찜) | 저장 수가 인기도 신호 | 사용자 반응 반영은 공식, 세부는 업계 추정 |
| 방문자 반응 | 클릭·길찾기·전화 등 | 상동 |
| 그 외 (사진 수·소식 빈도 등) | — | 업계 추정 — 확정처럼 말하지 않는다 |

- 정확한 가중치는 비공개다. **"이거 하면 1위 보장" 류의 컨설팅 멘트를 쓰지 않는다.** 통제 가능한 것(정보·리뷰 동선·소식)을 다 하고 결과를 기록한다.

## 4. 소식·쿠폰 — 살아있는 가게라는 신호 (LOC-04)
```bash
marketing-copilot library add content --json '{"title":"...","message_id":"MSG-...","channel":"local","format":"news","status":"draft"}'
```
- 소식: 신메뉴·이벤트·휴무·시즌 안내. 초안은 자동, 게시는 승인 후 사람이 센터 버튼으로. **빈도 목표를 두지 않는다** — 알릴 게 없으면 안 올린다(양치기 금지).
- 쿠폰: 오퍼(할인율·조건)는 마진 잠식 계산과 함께 설계한다 — [[promo]]. 수치는 products.md 마진 데이터로만.
- 소식에 넣는 외부 링크(홈페이지·예약 페이지)는 가능하면 UTM. 플레이스 내부 지표는 스마트플레이스 통계로 회수한다(LOC-11).

## 5. 리뷰 — 동선은 여기서, 운영은 [[review]] (LOC-05)
- 이 스킬이 하는 것: 플레이스 리뷰가 쌓이는 **동선 설계** — 결제·방문 직후 요청 타이밍, 매장 내 안내(QR 등), 요청 접점 배치.
- 요청 문구·체험단·부정 리뷰 대응·대가 표시 의무는 [[review]]가 전담한다. **대가를 걸면 표시 의무** — 경품·포인트·적립금도 대가다. 여기서도 예외 없다.
- 리뷰 답글은 자동 초안 → 승인 게시. 전체보다 최근·부정 리뷰 우선.

## 6. ★톡톡 마케팅 메시지 — 월 1회 무료 재방문 엔진 (LOC-06)
- **알림받기·최근 방문·최근 결제 고객에게 월 1회 무료 발송.** 알림톡 단가 없이 기존 고객 재방문을 돌리는, 이 채널에서 가장 저평가된 도구다.
- 매월 큐에 자동 등록: 이번 달 발송했는지 확인 → 소재(신메뉴·쿠폰·시즌) 선택 → 초안 → 승인 → 발송. **한 달을 그냥 보내면 무료 발송권 하나를 버린 것이다.**
- 광고성 메시지다 — (광고) 표기·전송자 정보 등 정보통신망법 요건과 톡톡 정책 세부는 [[publish-policy]]에서 검사하고, 불확실한 규정은 "확인 필요"로 남긴다. 야간(21시~08시) 발송은 피한다.
- 월 1회를 넘는 재방문 캠페인이 필요하면 [[alimtalk]](유료·동의자 대상)로 넘어간다.

## 7. 톡톡 상담 — 무료 문의 창구, 응대는 자동 초안 (LOC-07)
- 상담 문의는 구매 직전 신호다. 자주 묻는 질문(가격·주차·예약 가능 여부)을 FAQ로 정리해 응대 초안을 만들어 둔다.
- 반복 질문은 두 번 일하게 한다: 플레이스 정보·소식에 반영(정보 완성도로 환원) + 질문 자체가 고객 언어 신호 → [[signals]].

## 8. 블로그·다른 채널 연계 (LOC-08)

| 연계 | 무엇을 |
|---|---|
| [[blog]] 네이버 절(BLG-13~18) | "지역명+업종" 키워드 글 — 플레이스와 블로그가 같은 검색결과에서 두 자리를 차지한다 |
| [[instagram]] | 위치 태그·프로필 링크에 예약/플레이스 연결 |

| [[repurpose]] | 먹힌 소식·리뷰 표현을 다른 채널로 전개 |

## 9. 광고 — 무료 최적화가 끝난 다음에만 (LOC-09)
- 플레이스 광고·지역소상공인 광고는 **별도 광고비**(도구 이용료 0원). 정보 완성도·리뷰가 깔리기 전의 광고는 새는 돈이다 — 광고를 눌러 들어와도 빈 플레이스는 전환이 안 된다.
- 집행 전 손익분기 계산(객단가·마진·허용 CAC)은 [[opportunity]], 설계·중단조건·판정은 [[ads]]. 집행·증액은 [P] 승인.

## 10. 리스크 — 이 채널은 잃으면 복구가 없다 (LOC-10)

| 하지 말 것 | 왜 |
|---|---|
| 자작 리뷰·리뷰 구매 | 표시광고법 위반(제재 대상은 광고주) + 플레이스 제재로 노출 자체가 사라진다 |
| 대가 후기 미표시 | 같은 법 — 경품·포인트·적립금도 대가다. 표시 판정은 [[review]]·[[publish-policy]] |
| 순위 조작·트래픽 프로그램 | 비공식 자동화는 계정 제재 대상. "상위 노출 보장" 대행 영업은 거절한다 |
| 정보 거짓 기재(없는 편의시설·과장 설명) | 방문 후 실망은 부정 리뷰로 돌아온다 — 순위 요소를 스스로 깎는 짓 |

- 리뷰 대행·순위 보장 업체를 물어오면 이렇게 답한다: "그 돈이면 무료 최적화 + 정당한 리뷰 동선 + 톡톡 메시지가 남습니다. 걸리면 채널을 통째로 잃고 복구 수단이 없습니다."

## 11. 측정 — 순위·유입·전환 회수 (LOC-11)
- 주간 기록: 대표 키워드 순위(직접 검색으로 실측) · 플레이스 유입·유입 키워드(스마트플레이스 통계) · 전화(스마트콜) · 예약 수 · 톡톡 메시지 반응.
- 수치는 실측만 — 통계 화면에 없는 값은 "확인 필요". 성과는 소식·메시지의 `message_id`에 귀속하고([[messages]]), 판독과 다음 행동은 [[analyze]]·[[weekly-review]]로.

## LOC-12. 당근 비즈니스 — 동네 반경 하이퍼로컬, 전단지의 대체재

당근은 위치 기반이라 매장 반경 몇 km 안 이웃에게만 꽂힌다. 종이 전단·현수막을 대신하는 채널로 보면 된다. 개인 계정으로 하는 홍보(중고거래 글에 가게 끼워넣기 등)는 정책 위반이라 계정 정지 위험 — 사업자는 반드시 **비즈프로필**로 간다.

비즈프로필 개설·운영은 100% 무료(사업자 인증 없이도 생성 가능, 출처 확인 필요). 돈 나가는 건 **지역 광고**뿐.

| 지면 | 무엇 | 자동화 |
|---|---|---|
| 비즈프로필 | 가게 소개·영업시간·메뉴·위치. 검색·지도 노출의 그릇 | 정보 세팅 초안 자동, 게시 사람 |
| 소식 | 신메뉴·할인·공지 (피드 같은 것) | 초안 자동, 게시 승인 |
| 쿠폰 | 첫 방문·재방문 유도 | 초안 자동, 발행 승인 |
| 후기·답글 | 별점·후기에 답글 | 답글 초안 자동, 게시 사람 |
| 단골 | 소식 구독한 이웃 = 무료 리타깃 자산 | 관리 자동, 발송은 소식으로 |
| 동네생활 | 동네 Q&A·추천 글. 자연 노출은 [[comment]] 3모드 규칙 | 도움만/소속밝힘/게시안함 분류 |
| 지역 광고 | 비즈프로필·소식을 반경 내에 밀어주는 광고 | 집행·확대 승인 |

과금: 지역 광고는 클릭당 과금(CPC), 하루 소액(예: 5,000원)부터 시작 가능. 클릭 단가·도달 수치는 **당근비즈니스 대시보드에서 확인**(입찰·지역·업종마다 다름, 숫자 지어내지 말 것 — 시중 자료의 "클릭당 300~600원"은 대행사 블로그발이라 확인 필요).

당근은 코파일럿이 쓸 공개 마케팅 API가 없다(확인 필요) → **소식·쿠폰·답글 게시와 광고 집행은 전부 사람이 버튼**을 누른다. 코파일럿은 초안·문안·타이밍만 만든다.

자동화 범위:
- **초안 자동**: 비즈프로필 문구, 소식 카피, 쿠폰 조건, 후기 답글, 동네생활 답변(도움만 모드)
- **게시 승인(API 없는 지면 → 사람 버튼)**: 소식·쿠폰·답글 게시
- **광고 집행/확대 승인(돈)**: 지역 광고 예산·반경·증액

먹힌 소식·쿠폰 각도는 원장에 남긴다: `python library.py add asset --json '{...}'`. 반복 검증된 각도는 [[messages]]로 승격.

## LOC-13. 배달앱(배민·쿠팡이츠·요기요) — 배달·포장 업종만

배달·포장을 파는 곳만 해당. 홀 전용이면 건너뛴다.

먼저 사실 정정: **배민 울트라콜(월 정액 깃발)은 2025-07-31 전 지역 종료됐다.** 옛 자료가 울트라콜을 권하면 무시. 오늘(2026-08-03) 기준 구조:

| 앱 | 현재 노출/광고 상품 | 과금(확인 필요·변동) |
|---|---|---|
| 배민 | 오픈리스트(리스트 상단 노출) · 우리가게클릭(CPC) · 가게배달/배민배달(중개) | 오픈리스트 주문당 중개수수료(6.8% 보도), 우리가게클릭 클릭당 설정(200~600원 보도)·예산 하한 있음 |
| 쿠팡이츠 | 주문 연동형 광고(광고로 들어온 주문에만 과금) | 광고비율 % 설정형, 상세는 쿠팡이츠 광고센터 화면 확인 |
| 요기요 | 정액형·CPC형 혼재 | 매장별 편차 큼, 요기요 사장님사이트 확인 |

상품명·요율은 자주 바뀐다 → **각 사장님사이트/광고센터의 현재 화면을 사실검증**하고 지어낸 숫자로 편성하지 말 것(claims 밖 사실검증 = 사람).

리뷰 관리:
- 별점·리뷰 답글은 초안 자동, **게시는 사람**(코파일럿용 API 없음).
- 악성·허위 리뷰는 각 앱 신고 절차로. 삭제 요청 대필은 사실검증 후.

리뷰 이벤트(서비스·사은품 주고 리뷰 유도)는 **대가성 표시 의무**가 걸린다. 공정위 추천·보증 심사지침(2024-12-01 개정 시행)상 경제적 이해관계를 게시물 제목/첫 부분에 명확히 공개해야 하고, "소정의 수수료 지급 가능" 같은 모호한 표현은 규제 대상이다. 이건 **[[publish-policy]] 게이트의 법판정(사람)**으로 넘긴다 — 문안 초안은 자동, 게시 전 표시 문구 판정은 사람.

자동화 범위:
- **초안 자동**: 리뷰 답글, 리뷰 이벤트 문안(대가 표시 포함), 메뉴 설명·사진 발주 브리프([[imagefactory]])
- **게시 승인(API 없는 지면)**: 리뷰 답글·이벤트 게시
- **광고 집행/확대 승인(돈)**: 오픈리스트 on/off, 우리가게클릭 예산·단가, 쿠팡이츠 광고비율

## LOC-14. 지역 맘카페·지역 카페 — 대부분 유료 입점 게시판

지역 맘카페/네이버 지역 카페는 도달은 세지만 대부분 **제휴·입점업체 전용 게시판**으로 상업 글을 막는다. 3모드(도움만/소속 밝힘/게시 안 함)는 [[comment]], 지역카페 목록·등급은 communities-kr.md를 그대로 따른다.

| 접근 | 언제 | 처리 |
|---|---|---|
| 제휴 입점(유료 게시판) | 카페가 정식으로 업체 글 허용 | 입점료·게시 규칙 사실확인 → [[cafe]]로 연계 |
| 정보성 답변(도움만) | 회원이 추천 물을 때 | 소속 안 밝히고 진짜 도움만, 자기 가게 링크 금지 |
| 협찬·체험단 | 카페가 중개 | 대가성 표시 의무(LOC-13과 동일 법판정) |

핵심: **광고 금지 카페에 몰래 홍보 글 = 강퇴·차단**이라 계정 자산만 태운다. 코파일럿은 초안·답변만 만들고, **게시 여부·모드는 사람이 판정**(API 없는 지면 + 카페별 규칙 = 사실검증). 유료 입점 결정은 돈 → 승인.

## LOC-15. 네이버 예약·주문·스마트콜 — 무료 전환 완결 장치

노출을 만들어도 전화·예약이 안 걸리면 샌다. 스마트플레이스에 붙는 무료 전환 도구부터 켠다.

| 도구 | 역할 | 비용 |
|---|---|---|
| 네이버 예약 | 플레이스에서 바로 예약 (미용·병원·클래스·식당) | 무료(네이버페이 예약금 결제 시 결제수수료 여부는 확인 필요) |
| 네이버 주문 | 포장·매장·선주문 | 무료(결제 연동분 수수료는 확인 필요) |
| 스마트콜 | 050 가상번호 + 통화 통계(어느 채널서 전화 왔는지) | 무료(확인 필요) |

이건 광고가 아니라 **인프라**다. 한 번 걸어두면 노출→전화/예약까지 끊김 없이 이어진다. 스마트콜 통계는 어느 채널이 실제 전화를 만들었는지 귀속시켜 [[analyze]]의 근거가 된다.

자동화 범위: 예약 슬롯·주문 메뉴·안내 문구 **세팅 초안 자동**, 켜는 것/결제 연동은 계정 설정 → **사람 승인**. 예약 확정·노쇼 응대 문안은 초안 자동.

## LOC-16. 오프라인 ↔ 온라인 접점 — 매장 QR로 손님을 자산으로 회수

오프라인 손님을 온라인 자산(리뷰·채널·단골)으로 바꾸는 게 로컬의 진짜 복리다. 전단지는 뿌리면 끝이지만, 아래는 한 번 붙이면 계속 쌓인다.

| 접점 | 손님 → 자산 | 목적 |
|---|---|---|
| 매장 QR(테이블·카운터·포장백) | → 플레이스 리뷰 작성 | 리뷰 수·별점 = 노출·신뢰 |
| QR → 네이버 톡톡 채널 추가 | → 재방문 시 알림 발송 대상 | 무료 리타깃 |
| QR/스티커 → 당근 비즈프로필 단골 | → 소식 도달 대상 | 무료 리타깃 |
| 영수증·포장지 문구 | → 예약/주문 링크 | 다음 주문 전환 |

전단지 대체 공식: **종이 전단 → (당근 비즈프로필 + 소식) + (플레이스 + 리뷰 QR)**. 도달은 당근이, 신뢰·검색은 플레이스가 맡는다. 반경 밖까진 안 나가지만 로컬 장사는 그게 정답이다.

자동화 범위: QR 대상 URL·안내 문구·스티커 문안 **초안 자동**(디자인 발주는 [[imagefactory]]/simple-design). 실물 부착은 사람. 리뷰 유도 문구는 대가 없이 "리뷰 남겨달라"까지만 — 대가(서비스·사은품)를 주면 LOC-13 표시 의무로 넘어간다.

## LOC-17. 업종별 채널 우선순위 — 한 줄 배치

리소스는 한정됐으니 업종별로 1순위부터 깐다. 나머지는 후순위로 미룬다.

| 업종 | 우선순위(왼→오) | 이유 |
|---|---|---|
| 음식점(배달) | 플레이스 + 배달앱 + 당근 | 검색·전환은 플레이스, 주문은 배달앱, 반경 도달은 당근 |
| 음식점(홀 전용) | 플레이스 + 당근 + (지역카페) | 배달앱 제외, 반경 도달·단골 |
| 미용·병원(의원) | 플레이스 + 블로그 | 검색 후 예약 전환, 시술·후기 검색 수요는 블로그 |
| 학원·교습 | 지역 맘카페 + 플레이스 | 학부모 의사결정이 카페에서 남 |
| 소매·동네가게 | 당근 + 플레이스 | 하이퍼로컬 도달 + 검색 |

병원·의료는 의료광고 사전심의 등 규제가 별도다 → 문안은 초안까지만, **게시 전 법판정(사람)**. 확정 우선순위는 [[context]]의 업종·상권 값으로 다시 고정한다.
