# tiktok — 3초를 못 넘기면 나머지는 없다 (TIK-01~08)

숏폼은 **초반 이탈률이 곧 도달**이다. 3초에서 멈추지 않으면 남은 27초는 존재하지 않고, 그 이탈 기록이 계정 단위 품질 신호로 다음 게시물의 도달까지 깎는다([[method]]). 그래서 이 스킬은 대본을 예쁘게 쓰는 게 아니라 **3초 훅과 장면 순서를 설계하는 스킬**이다. 인스타와 마찬가지로 어댑터 — 메시지 정의는 [[idea]]에서 끝났고, 커버·썸네일 소재는 [[brief]]로 발주한다(TIK-07).

## 실행 유형: [A] 훅·대본·샷 리스트·자막·댓글 유도 설계와 콘텐츠 레코드 갱신은 질문 없이 실행 / [P] IF 발주(대외 지출 — 기본 per_item)와 게시는 승인. config `approval_mode` 적용. 유형별 차이는 [[role]].

## 0. 준비
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,tone,claims,audiences,channels}.md 2>/dev/null
marketing-copilot library list content --status drafting --limit 5
marketing-copilot library list signal --limit 10
```
- [[idea]]의 정의(목표·구매단계·메시지 ID·근거·CTA)가 없으면 그쪽 먼저. **촬영 가능한 것만 쓴다** — 사용자가 찍을 수 없는 장면(드론·모델·해외 로케)을 대본에 넣지 않는다.

## 1. 목적·길이 판정 (TIK-01)
| 길이 | 언제 | 구조 |
|---|---|---|
| **15초** | 한 방 — 반전·비포애프터·팁 하나 | 훅 3초 + 전개 9초 + CTA 3초 |
| **30초** | 기본값 — 문제→해법→증거 | 훅 3 + 문제 7 + 전개 12 + 증거 5 + CTA 3 |
| **60초** | 과정·해부·사례 (완주율이 떨어지므로 이유가 있어야 함) | 훅 3 + 챕터 3~4개 + CTA 5 |
- 길수록 좋은 게 아니다. **완주율이 도달을 만든다** — 30초로 충분하면 60초를 쓰지 않는다.

## 2. 3초 훅 (TIK-02) ★
- 후보 3개를 만들고 하나를 고른다. 유형: **결과 선공개**("이게 하루 만에 이렇게 됐습니다") / **반대 통념**("이거 하지 마세요") / **구체 상황 지목**("규격 맞추다 새벽 넘긴 적 있다면") / **시각적 이상**(첫 프레임이 궁금증을 만드는 장면).
- 3초 훅은 **말+화면 텍스트+첫 프레임 비주얼 세 개가 동시에** 작동해야 한다. 세 칸을 각각 적는다.
- **낚시 금지.** 훅과 본문이 어긋나면 이탈률이 튀고 계정 도달이 깎인다 — 단기 조회수보다 계정이 비싸다.

## 3. 대본·장면 순서 (TIK-03~04)
장면 표로 쓴다 — 이게 그대로 촬영 지시서가 된다:

| 초 | 비주얼(무엇을 보여주나) | 내레이션(무엇을 말하나) | 화면 자막 |
|---|---|---|---|
| 0~3 | {첫 프레임} | {훅} | {훅 텍스트} |
| … | … | … | … |

- **장면 전환은 2~4초에 한 번.** 같은 화면이 5초 이상 지속되면 이탈 구간이 된다.
- 순서 원칙(TIK-04): 결론 → 근거 → 과정 (설명 후 결론이 아니라 **결론 먼저**). 정보 밀도는 앞쪽에 몰고, 뒤로 갈수록 근거·디테일.
- **고유성 확보 지점**(퀄리티 바 ①): 대본 안에 우리만 보여줄 수 있는 실물·과정·데이터가 최소 하나. 없으면 보강 큐로 되돌린다.

## 4. 자막·온스크린 텍스트 (TIK-05)
- **무음 시청 전제** — 자막 없이 이해되지 않으면 대본이 아니다. 한 줄 12~16자, 화면당 2줄 이내.
- 화면 상단·하단 UI 가림 영역(세이프존)을 피해 배치 위치를 지정한다.
- 숫자·클레임 자막은 `claims.md` 원장 안의 것만. 근거 없는 수치는 자막에서 뺀다.

## 5. 댓글 유도 (TIK-06)
- 댓글은 알고리즘 신호이자 다음 콘텐츠의 재료다. **답이 갈리는 질문**(A vs B), **경험 소환**("이거 겪은 사람 손"), **의도적 여백**(마지막에 한 가지를 일부러 안 알려줌) 중 하나를 대본에 심는다.
- 어그로·논쟁 유발은 금지 — 댓글은 늘지만 브랜드가 상한다. `tone.md` 기준으로 검사한다.
- 반복 질문이 나오면 그게 다음 콘텐츠 주제이고, 축적형이면 [[blog]] 주제로 넘긴다(VIR-18 루프와 동일 사상). 댓글 대응은 [[comment]].

## 6. 밈·유행 차용 — 조건 4개 통과분만 (SIG-17)
[[signals]]가 등록한 밈·포맷·사운드 신호 중 **넷 다 통과한 것만** 쓴다: ① 브랜드 톤 적합성 ② 원작자·음원 권리 ③ 유행 잔여 수명(꺾인 밈에 올라타면 늦은 브랜드로 보인다) ④ 우리 메시지와의 연결 필연성. 하나라도 걸리면 쓰지 않는다 — **유행 편승 자체는 콘텐츠 근거가 아니다.**

## 7. 커버·썸네일 소재 — 발주 (TIK-07) ★자체 생성하지 않는다
```bash
marketing-copilot library add asset --json '{"brief_id":"BRF-...","type":"cover","spec":"1080x1920","copy":"커버 문구","status":"briefed"}'
```
- 커버·썸네일·엔드카드는 [[brief]] 표준 포맷으로 작성해 [[imagefactory]]에 발주한다. **발주는 대외 지출이므로 기본 per_item 승인.**
- 영상 촬영·편집 자체는 사용자(또는 외주)의 몫이다. 이 플러그인은 대본·샷 리스트·자막까지 만든다.
- 브리프는 표준 포맷이라 **IF가 아닌 어떤 제작사에게도 그대로 전달 가능**하다.
- 이미지팩토리가 밈·트렌드 분석 기반 SNS 소재 자동생성을 **연구 중**이다(2026-07-26 확인 — 미출시). 출시 시 TIK-07이 IF 직접 호출로 전환되도록 인터페이스만 맞춰 둔 자리이며, **미출시 기능을 현재형으로 안내하지 않는다**([[method]]).

## 8. 시리즈화·게시·측정 (TIK-08)
```bash
marketing-copilot library update content <CON-ID> --json '{"status":"ready","publish_date":"YYYY-MM-DD","utm":"utm_source=tiktok&utm_medium=organic&utm_campaign=..."}'
```
- **성과가 확인된 뒤에 시리즈로 만든다.** 1편 반응이 계정 평균 이상일 때만 2·3편 포맷을 고정하고 [[calendar]]에 리듬으로 배치한다 — 반응 없는 포맷을 시리즈로 밀면 계정 도달만 태운다.
- 게시 전 [[publish-policy]] 게이트(클레임·표시 의무·브랜드·플랫폼 정책·퀄리티 바 5항목·승인 모드). **자동 게시는 없다(V1)** — 사람이 올린다.
- 게시 후 24시간·7일 성과 슬롯(ANA-16). 완주율·저장·공유·댓글을 함께 기록하고 성과는 메시지 ID에 귀속([[messages]], ANA-17). 파생 확장은 [[repurpose]], 광고 전환 판단은 [[ads]].

## 원칙
- **3초가 전부다.** 훅이 약하면 대본을 다듬는 게 아니라 훅을 다시 만든다. 낚시로 3초를 사면 이탈률로 계정이 값을 치른다.
- **촬영 가능한 것만 쓴다.** 사용자가 못 찍는 장면을 대본에 넣으면 그 콘텐츠는 영원히 안 나온다 — 실행 가능성이 대본의 조건이다.
- **밈 편승은 근거가 아니다.** 조건 4개를 통과 못 한 밈은 쓰지 않는다. 권리가 애매한 음원·영상은 사용 금지.
- **환각 금지.** 없는 사례·수치·후기를 만들지 않는다. 자막·내레이션의 수치는 `claims.md` 원장 안의 것만, 나머지는 "확인 필요".
- **표시 의무.** 협찬·광고물은 영상 초반과 캡션에 명확히 표시한다. 숨기는 옵션은 존재하지 않는다.
- **편수 목표 금지·측정 없는 게시 금지.** 매일 올리는 리듬은 지키되 편수를 목표로 두지 않고, 모든 게시물에 성과 슬롯과 메시지 귀속을 남긴다.
