# affiliate — 성과과금이라 밑지지 않는 채널, 단 두 함정만 막으면 (AFF-01~14)

어필리에이트·레퍼럴은 전환당 지불(CPA/CPS)이라 **광고비 선지출 리스크가 없고 손익분기가 구조적으로 보장**된다 — 커미션을 허용 CAC 안에서 설계하면 ‘밑지는 획득’이 원천적으로 안 나온다. 이 플러그인의 ‘손익 먼저’ DNA에 가장 잘 맞는 채널이다.

단 두 가지가 이 채널을 망친다. ① 커미션을 감으로 정해 마진을 깎아먹기 ② **라스트클릭 하이재킹·쿠폰 남용** — 원래 살 매출에 수수료만 얹기. 이 스킬은 둘 다 막는다.

## 실행 유형: [A] 커미션 역산·파트너 정책·증분 검산·대가표시 가이드 초안은 자동 / [P] 파트너 계약·커미션율 확정·정산은 승인 후(대외 지출) / [H] 대가표시 의무 이행 확인·개인정보. 유형별 차이는 [[role]].

## 0. 준비
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,products,claims,goals}.md 2>/dev/null
python3 "$CLAUDE_PLUGIN_ROOT/scripts/econ.py" cac --aov 50000 --margin 0.3   # 허용 CAC = 커미션 상한
```

## 1. ★커미션율 = 허용 CAC 역산 (AFF-01~03) — 돈 먼저

**감으로 “매출의 10%” 정하지 않는다.** 허용 CAC에서 역산한다.

```
허용 CAC = econ.py cac --aov {객단가} --margin {마진율}   # ads와 같은 스크립트
커미션 상한 = 허용 CAC (신규 획득 1건에 낼 수 있는 최대)
```

| 판단 | 원칙 |
|---|---|
| 정률(매출 %) vs **정액(건당 원)** | 정액이 마진 통제에 유리 — 할인·객단가 변동에 커미션이 안 흔들린다 |
| 정률로 갈 때 | **할인가 기준** 명시(정가 기준이면 할인 시 마진 초과) |
| 마진 계산 | 부가세 뺀 공급가. **커미션은 비용이라 마진에서 다시 빠진다** — 광고와 동시 집행 시 이중 획득비 주의 |
| **신규 한정** | 커미션은 신규 고객에만. 기존 고객 재구매에 수수료 주면 증분 0인 매출에 비용만 |

마진을 모르면 커미션을 설계하지 않고 “확인 필요”로 남긴다([[method]] 돈 공식).

## 2. ★라스트클릭 하이재킹·쿠폰 남용 방지 (AFF-04~08) — 이 스킬의 심장

어필리에이트의 고전 사기: 쿠폰·브랜드 검색·툴바로 **구매 직전에 자기 링크를 끼워넣어** 어차피 날 전환의 수수료를 채간다.

| 방지 장치 | 내용 |
|---|---|
| **기여창 축소** | 클릭 후 7일 등 짧게. **뷰스루 수수료 금지** |
| **쿠폰 정책** | 어필리에이트 전용 코드만 인정. 자사 쿠폰페이지·쿠폰 애그리게이터 트래픽 제외. 코드 단위 상한·1인 1회·조합 불가 |
| **브랜드 키워드 입찰 금지**(계약서) | 파트너가 우리 브랜드명으로 검색광고 못 걸게 — 안 그러면 우리 오가닉·직접유입을 유료로 되사는 꼴 |
| **증분 검증** | 어필리에이트 전환 중 신규 비율·첫구매 비율을 본다. 기존 고객·쿠폰유입 비율 높으면 카니발라이제이션 → 수수료 조정·해지 |
| **정산 전 검수** | 전환 로그를 실주문과 대조(취소·반품 차감 후 **net 정산**). 라스트클릭 로그 그대로 지급 금지 |

이건 [[ads]] 리타겟의 증분 함정과 같은 논리다 — “원래 살 사람에게 비용만 얹는가”를 항상 검산한다.

## 3. ★대가 표시 의무 (AFF-09~10 · [H] · [[publish-policy]] 연동)

공정위 추천·보증 심사지침 — 경제적 이해관계 있는 추천·보증은 표시 의무. **미래·조건부 대가(커미션·적립 예정)도 이해관계로 간주**되므로 레퍼럴·어필리에이트는 전부 해당한다.

- **문자매체(블로그·SNS)는 게시물 제목 또는 첫 부분에 공개** — 끝부분·해시태그 더미 속에 숨기면 불충분
- 파트너에게 표시 문구·위치를 **계약·가이드로 강제**: “유료광고/제휴/커미션 받음”을 상단에, 소비자가 쉽게 인식하게
- **우리 책임**: 광고주도 파트너의 미표시로 제재 대상이 될 수 있다 → 온보딩 시 표시 의무 고지 + **미표시 적발 시 정산 보류·해지** 조항
- [[publish-policy]] 6단계 게이트의 ‘표시 의무’를 어필리에이트 소재에도 적용
- (개정 세부·시행 현황은 시점별 상이 — 집행 전 현재 지침 [확인 필요], 법무는 별도)

> **레퍼럴(고객→지인 추천)은 성격이 조금 다르다** — 친구 추천 리워드는 상업적 추천보증과 결이 다르지만, 리워드가 대가인 이상 안전하게 표시하는 쪽으로 설계한다.

## 4. 국내 서비스·세팅 (AFF-11~12)

| 유형 | 서비스 | 쓰임 |
|---|---|---|
| 고객 추천(레퍼럴) | **채널톡 ‘추천하기’**, 리퍼럴 SaaS | 기존 고객→지인 초대, 양방향 리워드. B2C 앱·커머스 |
| 인플루언서·제휴 | 국내 어필리에이트 네트워크·공구·체험단 플랫폼 | 정액·정률 CPS, 링크·코드 트래킹 |
| **자체 코드**(소규모) | 파트너별 전용 쿠폰코드 + UTM | 직접 관리, 저마찰 |

- 서비스 실비용·기능·정산 방식은 시점별 상이 → 계약 전 [확인 필요].
- 채널톡을 이미 상담 채널로 쓰면([[crm]]) 추천 기능 추가가 저마찰이다.
- 자체 코드는 `utm_content`에 파트너 ID + 메시지 ID를 붙여 [[analytics]] 규칙대로 귀속한다.

## 5. 측정·정산 (AFF-13~14)

```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" add performance --json '{"target_kind":"content","target_id":"AFF-...","message_id":"MSG-...","metrics":{"clicks":0,"conversions":0,"new_customer":0,"commission":0,"net_revenue":0},"source":"affiliate","note":"파트너별 net"}'
```

| 지표 | 왜 |
|---|---|
| 파트너별 전환·신규 비율 | 신규가 낮으면 카니발라이제이션 |
| net 매출(취소·반품 차감) | 정산 기준 |
| 실질 CAC = 커미션 ÷ 신규 전환 | 허용 CAC 안인지 |
| 브랜드 키워드·쿠폰유입 비율 | 하이재킹 감지 |

성과는 메시지에 귀속([[messages]]) — 어떤 오퍼가 파트너를 통해 먹혔는지 쌓는다.
