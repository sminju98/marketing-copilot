# linkedin — 글은 자동, 사람에게 말 거는 건 사람 (LIN-01~15)

B2B에서 링크드인은 **의사결정자가 실제로 있는 거의 유일한 지면**이다. 그리고 이 채널의 특징은 **회사 페이지가 아니라 개인 프로필이 이긴다**는 것이다 — 2026년 기준 개인 프로필 게시물이 회사 페이지 대비 도달 5~10배로 보고된다. 사람은 회사를 팔로우하지 않고 사람을 팔로우한다.

경계가 명확한 채널이기도 하다. **게시물 발행은 공식 API로 완전 자동이 되고, 커넥션 요청·DM은 공식 API에 기능 자체가 없다.** 이용약관 8.2조가 봇으로 메시지 보내는 것을 금지하고, 2026년 3월 링크드인이 대형 자동화 도구의 회사 페이지를 삭제하고 창업자 개인 계정까지 밴했다. 개인 계정이 날아가면 **쌓아온 인맥이 통째로 사라진다** — 복구 수단이 없다.

## 실행 유형: [A] 소재 정리·초안 3안 생성·성과 조회는 질문 없이 실행 / [P] 예약 발행은 승인 — config `approval_mode` 적용 / [H] **댓글·DM 응대는 사람이 직접**(자동화 금지 — 약관). 유형별 차이는 [[role]].

## 0. 준비
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,products,audiences,tone,claims}.md 2>/dev/null
marketing-copilot library list message --limit 10
marketing-copilot library list content --limit 20   # channel=linkedin 레코드를 골라 본다
```
- 지난 게시물을 먼저 본다 — **같은 각도를 반복하고 있지 않은지**가 첫 점검이다.
- 검증된 메시지 원장에서 각도를 고른다([[messages]]). 콘텐츠는 소모품, 메시지가 자산이다.

## 1. ★소재 — 자동 수집이 기본값, 사람 인풋은 선택 (LIN-01~03)

**사용자에게 "메모해두세요"를 요구하지 않는다.** 그건 안 지켜지고, 안 지켜지면 채널이 죽는다. 소재는 **기계가 먼저 가져오고**, 사용자는 원할 때만 한 줄 얹는다.

### 자동 수집 — 여기서 먼저 뽑는다 (LIN-01)

```bash
marketing-copilot library list signal --limit 20
```

| 소스 | 무엇 | 자동 |
|---|---|---|
| **[[signals]] 신호** | 업계 뉴스·정책 변화·경쟁사 움직임·키워드 트렌드 | 🤖 |
| **[[analyze]] 성과** | 지난주 뭐가 먹혔나 → 그 각도를 더 판다 | 🤖 |
| **[[messages]] 원장** | 검증된 메시지 중 링크드인에서 안 써본 각도 | 🤖 |
| **[[review]] 리뷰** | 고객이 실제로 쓴 표현·자주 나온 질문 | 🤖 |
| **[[opportunity]]** | 발굴된 기회의 배경 설명 | 🤖 |

**신호가 있으면 소재가 있다.** [[signals]]가 비어 있으면 그걸 먼저 돌린다 — 사용자에게 소재를 달라고 하지 않는다.

### 자동 소재를 글감으로 바꾸는 각도 (LIN-02)

수집된 신호를 그대로 옮기면 뉴스 요약이 되고 아무도 안 읽는다. **우리 관점을 붙여야** 글이 된다.

| 신호 | → 글감 |
|---|---|
| 업계 정책·규정 변화 | "이게 우리 같은 곳엔 이런 뜻입니다" |
| 경쟁사 움직임 | "우리는 왜 그 방향을 안 골랐나" |
| 키워드·검색 트렌드 | "사람들이 이걸 묻기 시작했다는 건" |
| 우리 성과 데이터 | "이렇게 해봤더니 이랬다" (claims 안에서만) |
| 반복되는 고객 질문 | "다들 이걸 묻습니다" |

**관점을 못 붙이면 그 신호는 버린다.** 남의 뉴스 요약은 도달만 깎는다(양치기 금지, [[method]]).

### 사람 인풋은 선택이다 (LIN-03)

사용자가 한 줄 던지면 그걸 **우선순위 1번**으로 올린다. 안 던져도 자동 소재로 돈다.

```bash
marketing-copilot library add signal --json '{"source":"work","note":"..."}'
```

특히 이런 건 기계가 절대 못 가져오므로, 사용자가 줄 때 반드시 저장한다.
- 실패·시행착오 ("이렇게 했다가 3주 날렸다") ← **반응이 가장 좋다**
- 의사결정의 이유 ("A와 B 중 A를 골랐고 왜")
- 미공개 경험

> **자랑은 안 읽히고 실패는 읽힌다.** 이게 이 채널의 유일한 규칙에 가깝다.
> 다만 실패담을 **지어내지 않는다** — 없으면 자동 소재로 간다.

## 2. 초안 — 서로 다른 각도 3안 (LIN-04~07)

같은 얘기 3번이 아니다. **각도가 달라야 한다.**

| # | 각도 | 형태 |
|---|---|---|
| 1 | **경험담** | 무슨 일이 있었고 → 뭘 했고 → 뭘 배웠나 |
| 2 | **역발상** | 다들 이렇게 하는데 → 우리는 이렇게 했고 → 이래서 |
| 3 | **실용** | 바로 써먹는 방법 N가지 |

### 구조 (LIN-05)

```
[첫 줄]      ← 여기가 전부다. 스크롤을 멈추게 한다.
(빈 줄)
[본문]       ← 문단당 1~3줄. 줄바꿈을 자주. 모바일에서 읽는다.
(빈 줄)
[마무리]     ← 질문으로 끝낸다. 댓글이 도달을 만든다.

#해시태그3개
```

### 규칙 (LIN-06)

- **800자 이내.** 넘으면 "더 보기"에서 잘리고 거기서 이탈한다
- 첫 줄에 결론이나 의외의 사실. `오늘은 ~에 대해 이야기해보려 합니다` 같은 도입부 금지
- 구체적인 숫자·상황. `claims.md` 원장 밖의 수치는 쓰지 않고 "확인 필요"로 남긴다
- 이모지 최대 2개, 해시태그 3개 (많으면 스팸으로 읽힌다)
- **판매 문구 금지** — 링크드인은 신뢰를 쌓는 곳이지 파는 곳이 아니다. `지금 문의하세요`를 넣는 순간 도달이 죽는다

### 반드시 마스킹 (LIN-07)

- **고객사 실명** → `[고객사 A]`로 처리하고 사용자에게 공개 동의 여부를 묻는다
- 계약 조건·단가·미공개 로드맵
- **이탈한 고객사를 레퍼런스로 쓰지 않는다** — 사실이 아닌 표시이자 분쟁 요인

## 3. 게시 게이트 (LIN-08)

[[publish-policy]]를 통과해야 게시한다. 이 채널 특화 항목:

```
□ 첫 줄만 봐도 멈추게 되나 (훅)
□ 800자 이내인가
□ claims.md 밖의 수치가 섞였나
□ 고객사 실명·계약조건이 들어갔나
□ 판매 문구가 들어갔나
□ 대가를 받은 게시물이면 표시했나
□ UTM이 붙었나 (링크가 있으면)
□ message_id를 연결했나
```

## 4. 예약 발행 — Buffer 경유 (LIN-09~11)

### 왜 Buffer인가 (LIN-09)

**링크드인 공식 마케팅 파트너**라 공식 API로 발행한다. 비공식 도구와의 차이가 여기다 — 정책 위반이 아니다.

- 무료 플랜: 채널 3개, 채널당 예약 10건 → **주 2회 리듬에 충분**
- MCP 주소 `mcp.buffer.com/mcp`를 커스텀 커넥터로 붙이면 대화로 예약된다 (OAuth라 API 키 복사 없음)

### 연결 (LIN-10)

없으면 [[setup]]으로 안내한다.
```
1. buffer.com 가입 → 링크드인 개인 프로필 연결 (회사 페이지 아님)
2. 설정 → 커넥터 → 커스텀 커넥터 추가 → mcp.buffer.com/mcp
3. Buffer 계정으로 로그인
```

### 한계 (LIN-11)

**Buffer MCP는 발행·예약 전용이라 성과 조회 엔드포인트가 없다.** 성과는 링크드인 자체 분석이나 별도 도구에서 가져와 수동 기록한다 — 측정 없는 게시 금지 원칙은 여기서도 유효하다.

## 5. ★절대 하지 않는 것 (LIN-12)

| 금지 | 결과 |
|---|---|
| **커넥션 요청 자동화** | 약관 8.2조 위반 → 계정 영구 정지 |
| **DM 대량 발송** | 약관 위반 + **정보통신망법 제50조**(광고성 정보, 3천만원 이하 과태료). SNS 쪽지도 전자적 전송매체다 |
| 프로필 스크래핑 | 계정 정지 + 개인정보 보호법 |
| AI 초안 무검수 대량 게시 | 계정 정지는 아니지만 **도달이 조용히 죽는다** |

**커넥션은 손으로 하루 10~15건.** 그 이상은 하지 않는다.

사용자가 자동화 도구를 물으면:
> 안 됩니다. 2026년 3월에 대형 자동화 업체의 회사 페이지가 삭제되고 창업자 개인 계정까지 밴됐습니다. 개인 계정이 날아가면 쌓아온 인맥이 통째로 사라지고 복구가 안 됩니다.
> 게시물 예약은 Buffer가 공식 파트너라 안전합니다. **글은 자동, 사람에게 말 거는 건 손으로.**

## 6. 댓글 — 여기가 도달을 만든다 (LIN-13)

링크드인 알고리즘은 **사람 대 사람 상호작용에 가중치**를 준다. 게시 후 첫 1~2시간의 댓글이 도달을 좌우한다.

- 댓글 알림이 오면 **24시간 안에 직접** 답한다 (자동화 금지)
- 짧은 감사 대신 **질문에 답하거나 되묻는다**
- 남의 글에 다는 진지한 댓글도 노출을 만든다 — 주 3~5개

## 7. 리듬과 측정 (LIN-14~15)

### 주간 리듬 (LIN-14)

| 언제 | 얼마 | 뭘 |
|---|---|---|
| 평소 | — | 소재 한 줄씩 |
| 화·목 | 각 30분 | 초안 3안 → 1개 골라 다듬기 → 예약 |
| 매일 | 5분 | 댓글 직접 답하기 |

**편수 목표를 두지 않는다.** 쓸 게 없으면 안 쓴다.

### 기록 (LIN-15)
```bash
marketing-copilot library add content --json '{"channel":"linkedin","status":"published","title":"...","message_id":"MSG-..."}'
```
| 지표 | 왜 |
|---|---|
| 노출·조회 | 도달이 유지되는지 |
| 댓글 수 | ★알고리즘 신호이자 실제 관심 |
| 프로필 조회 | 게시물 → 프로필 → 문의 경로의 중간 지표 |
| **인바운드 DM·문의** | 이게 돈이다 |

성과는 콘텐츠가 아니라 **메시지에 귀속**한다([[messages]]). 어떤 각도가 먹혔는지를 원장에 쌓는다.
