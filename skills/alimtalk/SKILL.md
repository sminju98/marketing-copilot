# alimtalk — 정보성과 광고성 사이에 3천만원이 있다 (ALT-01~18)

B2C 온라인에서 알림톡은 **도달률이 가장 높은 채널**이다. 이메일 개봉률이 20%대일 때 알림톡은 카카오톡 알림으로 바로 뜬다. 그래서 **재구매·리텐션의 주력**이고, 신규 획득보다 CAC가 압도적으로 낮다.

그런데 이 채널의 위험은 계정 정지가 아니라 **법**이다. 정보성 메시지는 수신동의 없이 보낼 수 있지만, **하단에 광고 한 줄만 끼워도 메시지 전체가 광고성으로 판정**되어 사전동의·(광고)표기·수신거부·야간금지가 전부 소급 적용된다. 위반은 3천만원 이하 과태료다.

**그래서 이 스킬의 첫 단계는 문구 작성이 아니라 판정이다.**

## 실행 유형: [A] 정보성/광고성 판정·템플릿 설계·시나리오 설계·단가 계산·성과 조회는 질문 없이 실행 / [P] 템플릿 등록과 실제 발송은 승인 — config `approval_mode` 적용 / [H] 광고성 발송은 수신동의 근거를 사람이 확인한 뒤에만. 유형별 차이는 [[role]].

## 0. 준비
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,products,audiences,tone,claims,channels}.md 2>/dev/null
marketing-copilot library list message --limit 10
marketing-copilot library list content --limit 20   # channel=alimtalk 레코드를 골라 본다
```
- `channels.md`에 **카카오 채널 개설 여부·발신프로필 등록 여부·발송사**가 없으면 [[context]]로 먼저 등록한다.
- 발송 이력을 먼저 본다 — **같은 고객에게 이번 달 몇 번 보냈는지**가 다음 판단의 전제다. 빈도가 피로도를 만든다.

## 1. ★가장 먼저 — 정보성인가 광고성인가 (ALT-01)

문구를 쓰기 전에 이 판정을 한다. **판정이 틀리면 나머지가 전부 위법이다.**

**경계는 "혜택 얘기냐 아니냐"가 아니다. 이미 준 것이냐, 새로 주는 것이냐다.**

| | 정보성 | 광고성 |
|---|---|---|
| 기준 | 수신자가 **이미 가진 것·이미 한 행동**에 대한 고지 | **새로 사게 하려는** 내용 |
| 사전 수신동의 | **불필요** | **필수** |
| (광고) 표기 | 불필요 | **필수** — 맨 앞에 텍스트로 |
| 무료 수신거부 | 불필요 | **필수** |
| 야간(21~08시) | 가능 | 별도 동의 없으면 금지 |

### 정보성으로 나가는 것 (ALT-01a)

```
주문·결제 완료          배송 출발·완료·지연
예약 확인·변경          취소·환불 처리
A/S 접수·완료           회원가입·본인 인증
멤버십 등급 변동         약관·거래조건 변경
재입고 알림 (신청자)

★ 보유 포인트·마일리지 소멸 예정 안내
★ 보유 쿠폰 만료 예정 안내
```

**마지막 두 줄이 실무의 핵심이다.** 이미 부여된 혜택이 소멸된다는 것은 **수신자의 재산적 권리가 사라진다는 사실 고지**이므로 정보성이다. 재구매를 유도하는 실질 효과가 있어도 마찬가지다 — 이건 회피가 아니라 정당한 분류다.

### 광고성으로 나가는 것 (ALT-01b)

```
신규 쿠폰 지급           할인·기획전·이벤트
신상품 소개              재구매 권유
리뷰 작성 시 적립금       친구 추천 리워드
```

### 소멸 안내를 쓸 때의 안전선 (ALT-01c)

소멸 안내에 **무엇을 얹느냐**로 성격이 바뀐다.

```
✅ "고객님의 적립금 3,000원이 8/31 소멸됩니다. [내 적립금 확인]"
   → 소멸 사실 + 사용처(내 페이지) 안내까지. 정보성

⚠️ "적립금 3,000원 소멸 전! 지금 인기상품 보러가기 →"
   → 상품 추천·구매 유도가 붙으면 광고 성격이 섞인다

❌ "적립금 소멸 임박! + 오늘만 추가 20% 쿠폰 드려요"
   → 신규 혜택 지급이 붙었으므로 광고성
```

**안전선: 소멸 사실 + 잔액 + 소멸일 + 내 계정 페이지 링크.** 여기까지는 정보성이고, 특정 상품·신규 할인을 얹으면 광고성 요건을 갖춰서 보낸다.

### 섞였을 때 (ALT-01d)

한 메시지에 정보성과 광고성이 섞이면 **전체가 광고성**으로 판정된다. 그래서 섞지 않고 **템플릿을 나눈다.**

```
[정보성] 주문 완료 안내           → 전체 구매자
[광고성] (광고) 재구매 쿠폰       → 동의자만
```

애매하면 광고성 요건을 갖춰 보낸다 — 갖추고 보내는 건 문제가 없지만 반대는 위법이다.

> 판정 결과를 사용자에게 **반드시 명시하고 시작한다**: "이건 광고성입니다. 수신동의 받은 명단에만 나갑니다."

## 2. 발송사와 단가 (ALT-02)

**개발 없이 웹에서 쓸 거면 알리고, 자동화에 붙일 거면 솔라피.**

| 발송사 | 알림톡 | 특징 |
|---|---|---|
| **알리고** | **6.5원** | 최저가. 웹 화면에서 대량 발송. 최소 5만원 선충전 |
| 뿌리오 | 7.3원 (VAT 포함) | 유선 고객지원. 단가 구간 폭이 넓어 상담 필요 |
| 비즈엠 | 8원 | 카카오 공식 딜러사. 가입 시 100건 무료 |
| **솔라피** | 13원 → **직접연동 8원** | API·n8n 노드. **반드시 카카오 채널 직접연동으로 세팅** |

**단가 계산은 econ으로 붙인다** — 발송 1건당 6.5~8원이므로, 재구매 1건의 공헌이익이 발송 비용의 몇 배인지 먼저 계산한다.
```bash
marketing-copilot econ --help
```
- 예: 공헌이익 10,000원 / 발송 단가 6.5원이면 **1,538건 보내서 1건만 사도 본전**이다. 이 구조가 알림톡이 리텐션 주력인 이유다.
- 다만 **피로도는 돈으로 안 잡힌다** — 차단·수신거부는 영구 손실이다. 빈도 상한을 먼저 정한다(ALT-11).

> ⚠️ 친구톡은 2025-12-31 종료되고 **브랜드메시지**로 전환됐다. 단가가 크게 올랐으니(구체 요금은 발송사 현행 공지 [확인 필요]) 예전 친구톡 물량 계획을 그대로 쓰면 예산이 튄다.

## 3. 템플릿 설계 (ALT-03~06)

알림톡은 **템플릿 사전심사**를 통과해야 발송된다. 심사에 며칠 걸리므로 **필요해지기 전에 등록해 둔다.**

### 3-1. 심사 통과하는 템플릿 (ALT-03)

| 통과 | 반려 |
|---|---|
| 변수 자리를 `#{이름}` 형태로 명확히 | 변수 없이 특정 고객 얘기 |
| 발생한 사실만 서술 | 광고 문구가 정보성 템플릿에 섞임 |
| 채널 정보·문의처 포함 | 발신 주체가 불명확 |
| 링크가 자사 도메인 | 단축 URL·외부 링크 |

### 3-2. 처음 만들 템플릿 4개 (ALT-04)

B2C 온라인이면 이 4개로 시작한다. 더 늘리는 건 이게 도는 걸 본 뒤에.

| # | 템플릿 | 유형 | 언제 |
|---|---|---|---|
| 1 | 주문 완료 | 정보성 | 결제 즉시 |
| 2 | 배송 출발 | 정보성 | 송장 등록 시 |
| 3 | 구매 후기 요청 | **정보성 경계** | 배송완료 +3일 |
| 4 | (광고) 재구매 안내 | **광고성** | 소진 예상 시점 |

> **3번 주의** — 후기 요청 자체는 정보성으로 보는 시각이 있으나, **후기 작성 시 적립금·쿠폰을 준다고 쓰는 순간 광고성**이다. 대가를 걸면 광고성 요건을 갖춰서 보낸다.

### 3-3. 문구 작성 규칙 (ALT-05)

- **첫 줄에 무슨 일인지** — 카톡 알림 미리보기에 첫 줄만 보인다
- 변수는 `#{고객명}` `#{상품명}` `#{배송사}` `#{송장번호}` 형태
- 링크는 **딱 하나**. 두 개 이상이면 클릭이 분산된다
- 이모지는 최대 1개
- `claims.md` 원장 밖의 수치·효능은 쓰지 않는다

### 3-4. 광고성 템플릿 필수 요소 (ALT-06)

광고성이면 이 4개가 **전부** 들어가야 한다. 하나라도 빠지면 위반이다.

```
(광고) ← 맨 앞에 텍스트로. (광-고), [광고], 이미지 표기 전부 불가

[본문]

▶ 무료 수신거부: #{수신거부번호 또는 링크}
발신: #{사업자명} #{연락처}
```

## 4. 시나리오 — B2C 온라인의 돈줄 (ALT-07~11)

### 4-1. 재구매 (ALT-07) — 가장 확실한 수익

```
트리거: 마지막 구매 + 소진 예상일
대상:  광고 수신동의자
문구:  (광고) #{상품명} 쯤 다 쓰셨을 때네요
효과:  신규 획득 CAC의 몇 분의 일
```

**소진 예상일을 모르면 이 시나리오를 만들지 않는다.** 아무 때나 보내면 피로도만 쌓인다. 상품별 재구매 주기를 `products.md`에 먼저 기록한다([[context]]).

### 4-2. 장바구니 이탈 (ALT-08)

```
트리거: 장바구니 담고 N시간 경과, 미결제
주의:  이건 광고성이다 (사지 않은 것을 사게 하려는 것)
빈도:  1회만. 두 번째부터는 차단을 부른다
```

### 4-3. 첫 구매 후 관계 만들기 (ALT-09)

```
D+0  주문완료        [정보성]
D+2  배송출발        [정보성]
D+5  잘 받으셨나요   [정보성 — 대가 없는 확인]
D+7  후기 요청       [대가 걸면 광고성]
```

### 4-4. 휴면 깨우기 (ALT-10)

```
트리거: 마지막 구매 N개월 경과
주의:  ★2년 이상 미접촉이면 수신동의가 만료됐을 수 있다
       정보통신망법상 2년마다 수신동의 재확인 의무
대응:  깨우기 전에 동의 재확인부터
```

### 4-5. 빈도 상한 — 반드시 먼저 정한다 (ALT-11)

| 유형 | 상한 |
|---|---|
| 정보성 | 사건당 1회 (제한 없음, 사건이 있을 때만) |
| **광고성** | **월 2회 이하로 시작.** 늘리려면 차단율을 보고 |

**차단·수신거부율이 발송당 1%를 넘으면 즉시 빈도를 줄인다.** 이건 되돌릴 수 없는 손실이다.

## 5. ★법 게이트 — 발송 전 자동 검사 (ALT-12~14)

[[publish-policy]]와 같은 원리로, 발송 전에 이 검사를 통과해야 한다.

```
□ ① 유형 판정      정보성 / 광고성 — 명시했나
□ ② 동의 근거      광고성이면 수신동의자 명단인가, 동의 시각 기록이 있나
□ ③ (광고) 표기    광고성이면 맨 앞에 텍스트로 들어갔나
□ ④ 수신거부       무료 수신거부 방법이 명시됐나
□ ⑤ 발송 시각      광고성이 21~08시에 걸리나 (야간 별도동의 없으면 차단)
□ ⑥ 2년 재확인     마지막 동의가 2년을 넘겼나
□ ⑦ 클레임         claims.md 밖의 수치·효능이 섞였나
□ ⑧ 빈도           이 고객에게 이번 달 몇 번째인가
```

**하나라도 미달이면 발송하지 않고 보강 큐로 보낸다.** 위반 시 3천만원 이하 과태료이고, 과태료보다 무서운 건 **채널 차단**이다.

### 자주 걸리는 것 (ALT-13)

| 실수 | 결과 |
|---|---|
| 정보성 템플릿 하단에 쿠폰 안내 | 전체가 광고성 → 동의 없는 발송 = 위반 |
| 명함·상담으로 받은 번호에 광고 발송 | **명함 교환은 수신동의가 아니다** |
| (광-고), [광고] 변칙 표기 | 표기 의무 미이행 |
| 밤 10시에 할인 알림 | 야간 별도동의 없으면 위반 |
| 구매 리스트에 광고 발송 | 구매 사실이 광고 수신동의는 아니다 |

### 사용자가 "그냥 보내면 안 되냐"고 하면 (ALT-14)

> 정보성이면 지금 보낼 수 있습니다. 광고성이면 동의받은 명단에만 나갑니다.
> 과태료도 문제지만, 신고가 쌓이면 카카오가 채널을 막습니다. 그러면 정보성 주문알림도 못 나갑니다 — **재구매 채널 자체를 잃는 겁니다.**
> 동의 명단이 작으면, 지금부터 주문 페이지에서 동의를 받아 쌓는 게 빠릅니다.

## 6. 발송과 승인 (ALT-15)

- **[P] 템플릿 등록**과 **실제 발송**은 승인 대상이다. config `approval_mode`를 따른다.
- **무인 실행 환경에서도 광고성 발송은 자동 집행하지 않는다** — 동의 근거 확인은 사람의 판단이다.
- 발송 결과(성공·실패·차단)를 라이브러리에 기록한다.
```bash
marketing-copilot library add content --json '{"channel":"alimtalk","status":"published","title":"...","message_id":"MSG-..."}'
```

## 7. 측정 — 발송했으면 반드시 (ALT-16~18)

### 기록할 것 (ALT-16)

| 지표 | 왜 |
|---|---|
| 발송 수 | 비용 = 발송 수 × 단가 |
| 도달률 | 실패는 번호 품질 문제 |
| 클릭 수 | 링크에 **UTM 필수** |
| **구매 전환** | 이게 없으면 나머지는 의미 없다 |
| **차단·수신거부율** | ★가장 중요한 경보 지표 |

### UTM 규칙 (ALT-17)

링크에 UTM이 없으면 발송 성과가 통째로 사라진다.
```
utm_source=alimtalk&utm_medium=message&utm_campaign=#{템플릿명}
```

### 메시지 귀속 (ALT-18)

성과는 콘텐츠가 아니라 **메시지에 귀속**한다([[messages]]).
어떤 각도(가격·편의·소진시점·한정)가 먹혔는지를 원장에 쌓아야 다음 발송이 나아진다. `message_id`를 반드시 연결한다.
