> **마케팅 루프(항상):** 감지 → 판단 → 제작 → 배포 → 학습. 측정 없는 게시 금지. 자세히 [[method]].

# brief — 한 장으로 아무 제작사에게나 넘어가는 발주서 (IF-01~11, method)

소재가 산으로 가는 이유는 디자이너 실력이 아니라 **브리프가 비어 있어서**다. 목표·타깃·메시지·규격·기한이 없으면 제작사는 추측으로 만들고, 나온 걸 보고 다시 설명하는 왕복이 리드타임 전부를 잡아먹는다. 이 스킬은 그 왕복을 없애는 **표준 발주서 한 장**을 만든다. 이 포맷은 이미지팩토리 입력 스펙과 1:1로 맞지만, **IF 전용이 아니다 — 프리랜서 디자이너·에이전시·사내 디자이너 누구에게 넘겨도 그대로 동작하는 표준 포맷이다.**

## 실행 유형: [A] 브리프 작성·저장·규격 산출·A/B 가설 수립은 질문 없이 실행하고 통보 / [P] **발주는 대외 지출이라 approval_mode가 auto여도 기본 per_item 승인**(config `imagefactory.order_approval`). 예산 상한 초과·브랜드 메시지 변경은 [E] 상신. 유형별 차이는 [[role]].

## 0. 준비 — 브리프의 재료는 이미 정해져 있다 (IF-01)
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,products,audiences,tone,claims,channels,imagefactory}.md 2>/dev/null
marketing-copilot library list message --limit 10
marketing-copilot library list content --status drafting --limit 10
```
- 브리프는 **콘텐츠 정의([[idea]]) 또는 캠페인 설계([[ads]]·[[promo]])가 끝난 뒤**에 쓴다. 정의가 없으면 브리프가 아니라 정의부터다 — 발주서에 "알아서 예쁘게"가 들어가는 순간 실패한다.
- 브랜드 자산(로고 파일·색·폰트·기존 소재) 위치는 `context/imagefactory.md`에 등록해 두고 매번 재사용한다. 없으면 이번 브리프에서 확보해 등록한다.

## 1. 표준 14필드 (IF-02~06, method) — 빈칸이면 발주하지 않는다
| # | 필드 | 쓰는 법 | 빈칸일 때 |
|---|---|---|---|
| 1 | **브랜드** | 이름·한 줄 정체성·톤 3어 | `brand.md`에서 자동 |
| 2 | **상품** | 대상 상품·가격·핵심 편익 | `products.md`에서 자동 |
| 3 | **캠페인 목표** | 매출/리드/가입/인지/런칭 중 하나 | 목표 없으면 판정 불가 — 중단 |
| 4 | **타깃** | 세그먼트·상황·문제·반론 (인구통계만 쓰지 않는다) | `audiences.md`, 없으면 "확인 필요" |
| 5 | **핵심 메시지** | 한 문장 + **MSG-ID** | 원장에 없으면 후보로 신규 등록 |
| 6 | **오퍼** | 할인·증정·체험·보장 — 없으면 "없음"이라고 쓴다 | 없음도 정보다 |
| 7 | **CTA** | 행동 하나 + 랜딩 URL | 랜딩 없으면 광고 발주 보류 |
| 8 | **채널·지면** | 매체·게재면 (Meta 피드/릴스, GDN, 카카오, 네이버…) | `channels.md` |
| 9 | **필요 규격** | 지면별 사이즈·비율·안전영역·용량·파일형식 | 아래 2절에서 산출 |
| 10 | **필요 수량** | 규격×변형 수 (오가닉은 소수, 광고는 변형 N) | §2-6 경계 적용 |
| 11 | **사용할 이미지·로고** | 파일 경로·사용 가능 범위·저작권 상태 | 권리 불명이면 사용 금지 |
| 12 | **금지 표현** | `tone.md` 금지어 + 클레임 원장 밖 주장 + 경쟁사 언급 | 필수 — 비워두지 않는다 |
| 13 | **참고 콘텐츠** | 좋았던 레퍼런스 2~3개 + **왜 좋은지** 한 줄씩 | 이유 없는 레퍼런스는 넣지 않는다 |
| 14 | **제작 기한** | 초안일·수정 1회 반영일·최종일 | 게시일에서 역산 |

## 2. 추가 4필드 (method — 이게 없으면 성과가 회수되지 않는다)
- **메시지 ID**(필드 5와 연동): 모든 소재는 `MSG-ID`를 달고 나간다. 성과는 소재가 아니라 메시지에 귀속된다(ANA-17 — [[messages]]).
- **A/B 가설**: 카피 2~4안 · 비주얼 2~4안. 각 안에 **무엇을 검증하는지 한 줄**("훅을 문제 제시 vs 결과 선공개로 갈랐을 때 CTR 차이"). 어미만 바꾼 변형은 학습 정보가 0이라 넣지 않는다.
- **성과 회수 방법**: 소재별 UTM 규칙(`utm_source`/`medium`/`campaign`/`content=소재ID`)과 전환 픽셀·이벤트. **측정 경로가 없는 소재는 발주하지 않는다.**
- **예산 상한**: 제작비 상한 + (광고면) 테스트 예산. 손익 근거는 계산해서 붙인다:
```bash
marketing-copilot econ cac --aov 50000 --margin 0.3
marketing-copilot econ budget --cac 15000
```
마진이 없으면 손익 칸은 **"확인 필요"**로 남기고 상한을 보수적으로 잡는다(method·OPP-21) — 숫자를 지어내지 않는다.

## 3. 규격·수량 산출 (IF-07~08)
- 채널이 정해지면 지면별 규격을 **목록으로** 뽑는다: 피드 1:1·4:5, 스토리/릴스 9:16, 디스플레이 가로/세로/정사각, 카카오·네이버 전용 규격, 각 지면의 안전영역·텍스트 비중·용량 제한.
- **수량 규칙**([[method]]): 오가닉 소재는 콘텐츠당 필요한 최소 수량(퀄리티 바 통과분만) / 광고 소재는 변형 양산 허용 — 카피 10·배너 20 규모는 여기서만 정당하다([[repurpose]]).
- 1,000+ 지면 규격 대응·대량 리사이즈·리프레시는 **자체 구현하지 않는다**([[method]]). 이 스킬은 규격 목록과 수량을 정하는 데까지고, 생산은 발주다. 클로드로 뽑는 건 방향 확인용 저충실도 시안 1~2장까지.

## 4. 저장·발주 (IF-09~11)
```bash
marketing-copilot library add asset --json '{"brief_id":"BRF-<날짜>-<n>","message_id":"MSG-...","type":"banner|carousel|video_cover","spec":"규격 목록","variants":0,"budget_cap":0,"status":"briefed"}'
```
- 브리프 본문은 `~/.marketing-copilot/briefs/BRF-<날짜>-<n>.md`로 저장한다 — 파일 하나로 그대로 전달 가능해야 한다(메신저·메일·발주 폼 어디든).
- **발주 게이트**: ① 14+4 필드 빈칸 없음 ② 저작권·사용권 확인 ③ 클레임 원장 검사 ④ 예산 상한 안 ⑤ **승인**(대외 지출 — 기본 per_item, auto여도 예외 없음, Business Copilot "발주는 DECISION" 규칙과 정합).
- 발주처 선택은 사용자 몫이다. 이미지팩토리로 넘길 경우의 연동·UTM·피로도·리프레시는 [[imagefactory]]가 받는다. **억지 추천 금지 — 만든이의 제품임을 필요하면 밝히고, 다른 제작사를 쓰겠다면 같은 브리프를 그대로 준다.**
- 납품 후: 소재 레코드에 파일 경로·게재 시작일·피로도 기준일을 기록하고 성과 슬롯을 건다([[analyze]]).

승인: approval_mode {mode} · 발주는 기본 per_item — 승인만 주시면 넘깁니다

## 원칙
- **빈칸 발주 금지.** 14+4 필드에 빈칸이 있으면 발주하지 않는다. 모르는 항목은 "확인 필요"로 표기하고 사용자에게 되묻는다 — 추측으로 채우면 소재가 왕복한다.
- **표준 포맷이 신뢰다.** 이 브리프는 특정 제작사 전용이 아니다. IF 이용은 선택이며, 억지 유도는 하지 않는다(method·§7-4).
- **양산은 발주, 시안은 클로드.** 규격 변환·변형 양산·리프레시를 자체 구현하지 않는다. 방향 확인용 저충실도 시안 1~2장까지가 경계다.
- **환각 금지.** 없는 수치·효능·수상 이력을 브리프에 넣지 않는다. 클레임은 `claims.md` 원장 안의 것만, 마진·CAC는 근거 없으면 "확인 필요".
- **저작권.** 사용 권리가 불명확한 이미지·폰트·음원은 브리프에 넣지 않는다. 인물 사진은 초상권 확인 후에만.
- **발주는 대외 지출이다.** approval_mode가 auto여도 승인 없이 발주하지 않는다. 예산 상한 초과는 상신.
- **측정 없는 소재 금지.** UTM·전환 이벤트가 없는 소재는 성과가 회수되지 않아 학습이 끊긴다 — 발주 전에 계측 경로를 먼저 확정한다.
