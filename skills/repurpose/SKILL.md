# repurpose — 원본이 아니라 메시지를 재활용한다 (REP-01~12)

"반응 좋았던 글을 다른 포맷으로 다시 쓴다"는 절반만 맞다. 잘 된 게 **그 카드뉴스**였는지 **그 메시지("소재 리드타임 단축" 같은 각도)**였는지 구분하지 못하면, 껍데기만 복제하고 성과는 재현되지 않는다. 콘텐츠는 소모품이고 메시지가 복리 자산이다(PLAN §2-3). 그래서 이 스킬은 원본 탐지가 아니라 **메시지 탐지**에서 시작하고, 확장할 때도 **오가닉은 소수 정예·광고는 변형 양산**으로 갈라서 전개한다(PLAN §2-6).

## 실행 유형: [A] 메시지 탐지·원본 해부·파생 초안·기록은 질문 없이 실행하고 통보 / [P] 게시는 [[publish-policy]] + config `approval_mode`, IF 발주(배너·규격)는 대외 지출이라 기본 per_item. 유형별 차이는 [[role]].

## 0. 준비 — 성과가 붙은 것부터 (REP-01)
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" list message --limit 15
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" list content --status published --limit 20
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" unmeasured
```
- **성과가 기록된 콘텐츠만 재활용 후보다.** `unmeasured`가 잔뜩 나오면 재활용보다 성과 기록이 먼저다(ANA-16) — 근거 없이 우려먹으면 실패를 복제한다.
- 후보 선정 기준은 절대 수치가 아니라 **계정 평균 대비**(저장·공유·댓글·문의). 조회수만 높고 행동이 없던 것은 후보가 아니다.

## 1. ★메시지 귀속 판정 (REP-01) — 무엇이 먹힌 건가
성과가 난 게시물 하나를 놓고 셋 중 무엇 덕인지 가른다:
| 후보 | 판별 방법 | 재활용 방식 |
|---|---|---|
| **메시지(각도)** | 같은 메시지가 다른 채널·다른 포맷에서도 반응이 있었나 | ★전 채널 전개 — 이 스킬의 본령 |
| **포맷·연출** | 같은 포맷의 다른 주제도 잘 됐나 | 포맷만 재사용, 메시지는 새로 |
| **일회성 노출** | 외부 공유·알고리즘 운·시기 이슈 | 재활용하지 않는다 |
- 판정 결과를 메시지 원장에 기록한다 — 검증 횟수가 쌓인 메시지가 다음 분기의 카피·랜딩·콜드메일 첫 줄이 된다([[messages]], Sales와 양방향 동기화).
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" update message <MSG-ID> --json '{"uses":2,"proof":"CON-.. 저장률 계정평균 2.1배","status":"validated"}'
```

## 2. 원본 해부 (REP-02~03)
원본에서 재사용 가능한 부품을 분리해 둔다 — 이후 모든 파생이 이 부품에서 나온다:
- **각도 한 문장**(=MSG) · **근거**(데이터·사례·경험, 출처 등급 SIG-16) · **결정적 장면 1개**(before/after·숫자·인용) · **반론과 답** · **CTA와 계측 경로**.
- 부품이 3개 미만이면 확장하지 않는다 — 얇은 원본을 20갈래로 늘리면 전부 얇아진다.

## 3. 확장 매트릭스 (REP-04~08) — 오가닉과 광고를 갈라서
**1개 사례 →** 블로그 1 · 카드뉴스 2 · 틱톡 대본 3 · 커뮤니티 답변 5 · **광고 카피 10 · 배너 20**

| 파생 | 수 | 성격 | 게이트 |
|---|---|---|---|
| 블로그 | 1 | 축적형 — 검색 의도로 재구성, 원본보다 깊게 | **퀄리티 바 5항목 각각** ([[blog]]) |
| 카드뉴스 | 2 | 요약형 1 + 사례 해부형 1 | **퀄리티 바 5항목 각각** ([[instagram]]) |
| 틱톡 대본 | 3 | 훅 3종(문제 제시·반전·결과 선공개) | **퀄리티 바 5항목 각각** ([[tiktok]]) |
| 커뮤니티 답변 | 5 | 질문 맥락별 답변 — 개수 목표 아님 | 가치 판정 + 3모드 ([[comment]]) |
| 광고 카피 | 10 | A/B 변형 — 매체가 승자를 고름 | 클레임·표시 의무 ([[ads]]) |
| 배너 | 20 | 지면 규격·비주얼 변형 = IF 물량 | 브리프 발주 ([[brief]]→[[imagefactory]]) |

- **오가닉 파생(블로그·카드뉴스·대본·커뮤니티)은 "N개 채우기"가 아니다.** 각각이 [[idea]]의 퀄리티 바 5항목을 통과해야 하고, 미달분은 게시가 아니라 보강 큐다. 위 숫자는 상한이지 목표가 아니다 — 통과가 1개면 1개만 나간다.
- **변형 양산이 정당한 곳은 광고뿐이다**(PLAN §2-6): 매체 시스템이 예산을 승자 변형에 몰아주므로 패자 변형의 하방이 막혀 있다. 오가닉은 반대로 저품질이 계정 도달을 깎아 **0이 아니라 마이너스**다.
- 광고 카피 10종은 축을 나눠 만든다: **훅 유형 × 오퍼 표현 × 길이**. 같은 문장 어미만 바꾼 10종은 학습 정보가 0이다.

## 4. 채널별 말투 변환 (REP-09)
- 같은 각도라도 문법이 다르다: 블로그는 검색 의도와 목차, 인스타는 첫 장과 저장 이유, 틱톡은 3초와 무음 자막, 커뮤니티는 질문에 직접 답하기, 광고는 한 문장 안에 오퍼.
- **금지: 복붙 전개.** 블로그 문단을 카드에 그대로 붓거나, 카드 문구를 광고 카피로 그대로 쓰는 것은 퀄리티 바 ③(플랫폼 네이티브) 탈락이다.
- `tone.md`·`claims.md`는 파생마다 다시 검사한다. 원본이 통과했다고 파생이 자동 통과하지 않는다.

## 5. 배너·규격 — 발주로 넘긴다 (REP-10)
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" add asset --json '{"brief_id":"BRF-...","type":"banner","spec":"지면별 규격 목록","variants":20,"message_id":"MSG-...","status":"briefed"}'
```
- 배너 20종·리사이즈·리프레시는 **자체 구현하지 않는다**(PLAN §7-1). [[brief]] 표준 포맷으로 발주서를 쓰고 [[imagefactory]]로 넘긴다 — **브리프는 표준 포맷이라 다른 디자이너·제작사에게도 그대로 전달 가능하다.**
- 발주는 대외 지출이므로 기본 per_item 승인이고, 예산 상한을 브리프에 적는다.

## 6. 기록·성과 회수 (REP-11~12)
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" add content --json '{"title":"...","channel":"blog","format":"post","message_id":"MSG-...","parent_id":"CON-원본","status":"draft"}'
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" update message <MSG-ID> --json '{"uses":<파생 누계>,"performance_note":"파생 CON-.. / CON-.."}'
```
- 모든 파생에 **원본 링크(`parent_id`)와 메시지 ID**를 건다. 성과는 파생 콘텐츠가 아니라 메시지에 누적된다(ANA-17).
- 판정 지표는 확장 배수가 아니라 **파생물 중 계정 평균 이상 성과 비율**(PLAN §11). 이 비율이 떨어지면 배수를 줄이고 원본 선별을 조인다.
- 재활용 주기: 축적형(블로그)은 분기 단위 업데이트, 속도형(소셜)은 각도를 바꿔 재전개, 광고 소재는 피로도 도달 시 리프레시([[imagefactory]] `library.py fatigue`).

## 원칙
- **재활용의 단위는 메시지다.** 원본을 복제하지 말고 검증된 각도를 다른 문법으로 다시 만든다. 메시지 ID 없는 파생은 만들지 않는다.
- **오가닉은 소수 정예.** 확장 숫자는 상한이지 목표가 아니다. 퀄리티 바 미달 파생은 게시가 아니라 보강 큐 — 캘린더 빈칸을 채우려고 바를 낮추지 않는다(PLAN §13-3).
- **양산은 광고에만.** 매체가 승자를 골라주는 지면에서만 변형 N종이 정당하다. 오가닉 저품질 대량은 계정 도달을 깎아 다음 게시물까지 손해다.
- **양산·규격·리프레시는 자체 구현하지 않는다**(PLAN §7-1). 브리프로 발주하며, 브리프는 IF 전용이 아닌 표준 포맷이다.
- **환각 금지.** 원본에 없던 수치·사례를 파생에서 새로 만들지 않는다. 근거는 원본 부품에서만 가져오고, 부족하면 "확인 필요".
- **측정 없는 게시 금지.** 파생마다 UTM·성과 슬롯을 건다. 파생 성과 비율이 계속 낮으면 재활용을 멈추고 원본 선별로 돌아간다.
