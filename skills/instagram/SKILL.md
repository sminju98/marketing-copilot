> **마케팅 루프(항상):** 감지 → 판단 → 제작 → 배포 → 학습. 측정 없는 게시 금지. 자세히 [[method]].

# instagram — 두뇌는 여기, 소재는 발주 (INS-01~10)

인스타는 **어댑터**다([[method]]) — 루프는 [[idea]]에서 이미 돌았고, 여기서는 정해진 메시지를 인스타 문법으로 옮긴다. 구조·훅·문구·캡션·해시태그·대본까지가 이 스킬의 범위이고, **이미지 소재 자체는 만들지 않는다**(INS-08~09는 브리프 발주 — method). 카드뉴스는 첫 장에서 끝나고, 릴스는 3초에서 끝난다. 그 두 개를 못 넘기면 나머지 장·나머지 초는 아무도 안 본다.

## 실행 유형: [A] 구조·훅·문구·캡션·해시태그·대본 작성과 콘텐츠 레코드 갱신은 질문 없이 실행 / [P] IF 발주(대외 지출 — 기본 per_item)와 게시는 승인. config `approval_mode`·`imagefactory.order_approval` 적용. 유형별 차이는 [[role]].

## 0. 준비 — 정의를 받아온다
```bash
cat "${MKT_COPILOT_HOME:-$HOME/.marketing-copilot}/context/"{brand,tone,claims,audiences,channels}.md 2>/dev/null
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" list content --status drafting --limit 5
```
- [[idea]]의 CON 정의(목표·구매단계·메시지 ID·근거·훅·CTA)가 없으면 먼저 그쪽을 돌린다. **정의 없이 카드부터 짜지 않는다.**
- 과거에 반응이 좋았던 메시지가 있으면 그 각도를 재사용한다([[messages]]·[[repurpose]]) — 새 메시지보다 검증된 메시지가 우선.

## 1. 포맷 판정 (INS-01)
| 포맷 | 언제 | 분량 |
|---|---|---|
| **카드뉴스(캐러셀)** | 순서를 밟아야 이해되는 것 — 방법·비교·체크리스트·사례 해부 | 7~10장 |
| **릴스** | 한 장면으로 보여지는 것 — 변화·과정·현장·반전 | 15~45초 |
| **단일 이미지** | 한 문장으로 끝나는 선언·공지·오퍼 | 1장 |
| **스토리** | 원본의 파생 — 근황·투표·링크 유도 | 3~5컷 |
구매 단계도 같이 본다: 인지는 릴스·저장형 카드뉴스, 고려는 비교·사례 카드뉴스, 전환은 오퍼+링크 스토리 조합.

## 2. 카드뉴스 구조 (INS-02) — 한 장 한 메시지
```
1장 훅 → 2장 문제·공감(왜 이게 문제인가) → 3~7장 본론(한 장에 한 포인트, 각 장에 근거·예시 1개)
→ 8장 요약(한 화면으로 저장할 이유) → 9~10장 우리 관점·CTA
```
- 각 장은 **스크롤을 넘길 이유**로 끝난다(미완결·번호·"그런데"). 넘길 이유가 없는 장은 삭제한다 — 장수를 채우려 늘리지 않는다.
- 8장(요약 장)이 저장률을 만든다. "이 한 장만 저장해도 쓸모 있는가"가 기준.

## 3. 첫 장 훅 (INS-03)
- 후보 3개를 쓰고 하나를 고른다. 유형: **숫자·기간**("2주 만에 X") / **반대 통념**("A 하지 마세요") / **구체 상황**("소재 규격 맞추다 하루 날린 적 있다면") / **결과 선공개**("결론부터: …").
- 규칙: 문장 하나·읽는 데 2초 이내·**낚시 금지**(본문과 어긋나면 초반 이탈로 계정 도달이 깎인다). 수치는 `claims.md` 안의 것만.

## 4. 장별 문구 (INS-04)
- 장당 텍스트는 짧게(1~2문장), 화면에서 읽히는 크기를 전제로 쓴다. 문장 부호로 호흡을 만들고 전문용어는 풀어 쓴다.
- `tone.md` 금지 표현·과장 표현 검사. 최상급·효능 표현은 원장 근거가 있을 때만.
- **고유성 확보 지점**(퀄리티 바 ①): 본론 5장 중 최소 1장은 우리만 쓸 수 있는 경험·데이터·사례여야 한다. 일반론만 남으면 이 콘텐츠는 보강 큐로 되돌린다.

## 5. 릴스 대본 (INS-05)
```
0~3초 훅(화면에 텍스트로도 박는다) → 3~10초 문제·상황 → 10~25초 전개(장면 전환 2~4회)
→ 25~35초 증거·결과 → 마지막 3초 CTA 한 줄
```
- 장면별로 **무엇을 보여주는지(비주얼) + 무엇을 말하는지(내레이션) + 화면 자막**을 표로 분리한다. 자막은 무음 시청 전제.
- 유행 사운드·밈 포맷은 [[signals]]의 밈 조건 4개(톤 적합성·권리·잔여 수명·메시지 연결 필연성, SIG-17) 통과분만. 원작자·음원 권리가 애매하면 쓰지 않는다.

## 6. 캡션·해시태그·스토리 변형 (INS-06~07)
- **캡션**(INS-06): 첫 2줄이 두 번째 훅(더보기 전에 보이는 부분). 구조는 훅 → 본문 3~5줄(카드에 없는 맥락·뒷이야기) → CTA 한 줄 → 필요 시 표시 문구. 링크는 프로필로 유도하되 **UTM을 붙인 링크**를 쓴다(측정 없는 게시 금지).
- **해시태그**(INS-07): 대형(경쟁 심함)·중형·니치·브랜드 태그를 섞어 10~15개. **무관 태그·인기 태그 도배 금지**(플랫폼 정책 위반이자 도달 손해). 매 게시물 동일 태그 블록 복붙도 스팸 신호다.
- **스토리 변형**(INS-07): 원본에서 3~5컷 추출 — 훅 컷 / 핵심 1컷 / 투표·질문 스티커(댓글·DM 유도) / 링크 스티커(UTM). 스토리는 새 콘텐츠가 아니라 원본의 유통이다.

## 7. 소재 제작 — 발주 (INS-08~09) ★자체 생성하지 않는다
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" add asset --json '{"brief_id":"BRF-...","type":"carousel","spec":"1080x1350 x10","copy":"장별 문구 첨부","status":"briefed"}'
```
- **INS-08 소재 브리프**: [[brief]] 표준 포맷(브랜드·상품·목표·타깃·핵심 메시지·오퍼·CTA·채널·규격·수량·사용할 이미지/로고·금지 표현·참고·기한 + 메시지 ID·A/B 가설·성과 회수 방법·예산 상한)으로 작성한다.
- **INS-09 규격·변형 지시**: 캐러셀 1080×1350, 릴스 커버 1080×1920, 스토리 세이프존 등 지면 규격과 필요 변형 수량을 브리프에 명시 → [[imagefactory]]로 발주. **발주는 대외 지출이므로 기본 per_item 승인.**
- 이 플러그인은 소재 양산·리사이즈·리프레시를 자체 구현하지 않는다([[method]]). 클로드로 뽑는 것은 방향 확인용 저충실도 시안 1~2장까지다.
- 브리프는 **표준 포맷이라 IF가 아닌 어떤 디자이너·제작사에게도 그대로 전달 가능하다.** IF 이용은 선택이다.
- 이미지팩토리가 트렌드·키워드·시장·밈 분석 기반 SNS 소재 자동생성을 **연구 중**이다(2026-07-26 확인 — 미출시). 출시되면 INS-08~09가 브리프 발주 대신 IF 직접 호출로 전환되도록 인터페이스만 맞춰 둔 자리다. **미출시 기능을 현재형으로 안내하지 않는다**([[method]]).

## 8. 게시·측정 (INS-10)
```bash
python3 "$CLAUDE_PLUGIN_ROOT/scripts/library.py" update content <CON-ID> --json '{"status":"ready","publish_date":"YYYY-MM-DD","utm":"utm_source=instagram&utm_medium=organic&utm_campaign=..."}'
```
- 게시 전 [[publish-policy]] 게이트: 클레임 검사 → 표시 의무(협찬·광고 표기) → 브랜드 → 플랫폼 정책(해시태그 스팸·중복 도배) → **퀄리티 바 5항목** → 승인 모드. 하나라도 걸리면 게시가 아니라 보강 큐.
- **자동 게시는 없다(V1)** — 초안·소재·예약 시각까지 준비하고 사람이 올린다. 게시 후 24시간·7일 성과 기록 슬롯을 큐에 넣는다(ANA-16), 성과는 메시지 ID에 귀속([[messages]], ANA-17).
- 반응이 좋으면 파생 확장은 [[repurpose]], 광고로 밀 값어치가 있는지는 [[ads]]가 판정한다.

## 원칙
- **소재는 만들지 않고 발주한다.** 양산·규격·리프레시는 이미지팩토리 영역이고, 자체 구현은 대체 금지 위반이다([[method]]). 브리프는 표준 포맷이라 다른 제작사에도 그대로 쓸 수 있다.
- **편수 목표 금지.** 캘린더 빈칸을 채우려고 퀄리티 바를 낮추지 않는다. 채울 게 없으면 재활용([[repurpose]])과 보강 큐를 먼저 쓴다.
- **환각 금지.** 없는 사례·수치·후기를 만들지 않는다. 수치·최상급은 `claims.md` 원장 안의 것만, 나머지는 "확인 필요".
- **표시 의무.** 협찬·광고·경제적 이해관계가 있으면 캡션 앞부분에 명확히 표시한다(표시광고법·추천보증심사지침). 숨기는 옵션은 존재하지 않는다.
- **자동 게시·해시태그 스팸 금지.** 플랫폼 약관 위반은 계정 리스크다 — 계정이 죽으면 마케팅 전체가 죽는다.
- **측정 없는 게시 금지.** 모든 링크에 UTM, 모든 게시물에 성과 슬롯. 기록 없는 활동은 학습이 안 된다.
